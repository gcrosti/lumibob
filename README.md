# LumiBob

A lead/lag pairs-trading strategy built on [Lumibot](https://github.com/Lumiwealth/lumibot) and [Alpaca](https://alpaca.markets). LumiBob automatically discovers stock pairs where one ticker (the *lead*) predicts another (the *lag*), then trades the lag using moving-average crossover signals derived from the lead.

The goal of Lumibob is to maximize YOY revenue outcomes. 

## How It Works

Each trading day the strategy runs through three phases:

1. **Pair maintenance** — existing pairs are re-evaluated for correlation drift and updated with fresh buy/sell/hold signals.
2. **Pair discovery** — 10 new candidate pairs are screened from the full NYSE/NASDAQ universe. A pair must pass three gates: Pearson correlation >= 0.9, Engle-Granger cointegration, and positive simulated return via `PairSimulator`. Only the top candidates (up to `max_daily_candidates`) are added.
3. **Execution** — sell signals are acted on first to free capital, then buy signals are executed by deploying half of available cash and splitting it evenly across newly discovered pairs. Existing positions with a buy signal are also topped up using a gap-fill model: each day, a fraction (`top_up_rate`) of the remaining gap to a maximum position size (`initial_cost * max_position_multiplier`) is purchased, asymptoting toward the cap.

Signals are generated by a short/long moving-average crossover on the *lead* ticker's lagged price series. The optimal lag, short MA, and long MA for each pair are found via grid search in `PairSimulator.optimize()`.

## Architecture

```
main.py
└── BobsBrain (Lumibot Strategy)
      ├── DatabaseClient ──────────► PostgreSQL / TimescaleDB
      ├── AlpacaClient ───────────► Alpaca API
      ├── StockDataCache(db, alpaca)   read-through price cache
      ├── StockEvaluator               correlation, cointegration, MA signals
      └── PairSimulator                grid-search pair backtester
```

| Module | Responsibility |
|---|---|
| `BobsBrain.py` | Core strategy — pair lifecycle, order routing, daily snapshots |
| `AlpacaClient.py` | Thin wrapper around `alpaca-py` for asset listing and OHLCV retrieval |
| `DatabaseClient.py` | All PostgreSQL access — tickers, prices, pairs, runs, trades, snapshots |
| `StockDataCache.py` | Read-through cache: serves prices from the DB, backfills gaps from Alpaca |
| `StockEvaluator.py` | Lagged Pearson correlation, Engle-Granger cointegration, MA crossover action |
| `PairSimulator.py` | Simulates a pair over historical data; `optimize()` grid-searches parameters |

## Prerequisites

- Python 3.10+
- Docker (for TimescaleDB)
- An [Alpaca](https://alpaca.markets) account (paper-trading keys are fine)

## Quick Start

```bash
# 1. Clone and install dependencies
git clone <repo-url> && cd LumiBob
pip install -r requirements.txt

# 2. Start TimescaleDB
docker compose up -d

# 3. Apply the schema
psql postgresql://postgres:lumibob@localhost:5432/lumibob -f schema.sql

# 4. Configure environment
cp .env.example .env
# Edit .env and add your Alpaca API key + secret

# 5. Run a backtest
python main.py
```

## Configuration

All configuration is via environment variables (loaded from `.env`).

| Variable | Description | Default |
|---|---|---|
| `ALPACA_API_KEY` | Alpaca API key | *(required)* |
| `ALPACA_API_SECRET` | Alpaca API secret | *(required)* |
| `ALPACA_IS_PAPER` | Use Alpaca paper trading endpoint | `true` |
| `DB_URL` | PostgreSQL connection string | `postgresql://postgres:lumibob@localhost:5432/lumibob` |
| `RUN_MODE` | `backtest` or `paper` | `backtest` |

Strategy-level parameters (passed via `main.py`):

| Parameter | Description | Default |
|---|---|---|
| `ticker_limit` | Max tickers to screen during pair discovery | `100` |
| `min_correlation` | Minimum Pearson correlation to accept a pair | `0.9` |
| `lookback_window` | Days of price history for correlation/MA calculations | `60` |
| `min_daily_pairs` | Target number of new pairs to discover and buy per day | `10` |
| `max_lag` | Maximum lead-lag offset (days) to test | `5` |
| `max_position_multiplier` | Cap each position at this multiple of its initial cost | `3.0` |
| `top_up_rate` | Fraction of the gap to the position cap to buy each day | `0.5` |

## Execution Modes

### Backtest

Uses Lumibot's `YahooDataBacktesting` engine to simulate the strategy over a historical window. The default window in `main.py` is 2024-01-01 to 2024-06-30 with a $10,000 budget.

```bash
RUN_MODE=backtest python main.py
```

### Paper Trading

Connects to Alpaca's paper-trading API and runs the strategy live against real market data without risking real capital.

```bash
RUN_MODE=paper python main.py
```

## Database

LumiBob uses PostgreSQL with the [TimescaleDB](https://www.timescale.com/) extension for time-series data. The `docker-compose.yml` provides a ready-to-use local instance.

### Tables

| Table | Purpose |
|---|---|
| `tickers` | Tradeable symbol universe (refreshed from Alpaca) |
| `stock_prices` | OHLCV price cache (TimescaleDB hypertable, 90-day compression, 2-year retention) |
| `backtest_runs` | Run metadata — mode, date range, settings JSONB |
| `pairs` | Discovered lead/lag pairs with parameters and correlation |
| `portfolio_snapshots` | Daily portfolio value, cash, SPY benchmark, and indicators |
| `trades` | Individual fill records with slippage tracking |
| `failed_tickers` | Symbols that failed price fetching (skipped on future runs) |

### Schema Management

There is no migration framework. Apply `schema.sql` against a fresh database, and `DatabaseClient` handles minor idempotent migrations at startup.
